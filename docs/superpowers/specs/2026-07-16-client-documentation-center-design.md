# 甲方文档中心设计

## 目标与边界

为 SleepFM-Clinical 增加面向甲方的中文文档体系和独立 Web 阅读入口。Markdown 是唯一内容源，前端只负责从 API 获取并渲染，不在 HTML 中复制正文。不改模型推理逻辑，不新增训练 API，不调整 Docker 或 systemd。

## 文档信息架构

新增三份顶层文档：

- `docs/使用文档.md`：快速开始、控制台与各推理接口、参数、文件复用、导出和 FAQ。
- `docs/模型算法.md`：PSG 预处理、通道无关编码、LOO-CL、下游 LSTM、睡眠分期与 CoxPH 疾病预测。
- `docs/训练与调优.md`：预训练、嵌入生成、下游微调、配置与评估，并给出甲方发起调优请求时的数据、目标、指标、资源和验收清单。

同时更新 `docs/接口文档.md`，按代码修正独立子任务接口的 `accepted + task_id` 和 `/subtask_result/{task_id}` 轮询流程；更新 `docs/部署文档.md` 与 `docs/测试指南.md`，补充文档中心部署与验证。`docs/任务进度.md` 保持内部用途，不通过甲方文档接口发布。

算法背景以原型仓库与公开论文为依据，服务参数和接口行为以本仓库代码、`api/config.py` 及路由实现为准。论文训练配置与仓库示例配置明确区分，示例中的绝对路径必须提示使用者替换。

## 后端设计

新增只读文档路由，挂载在 `/api/v1`：

- `GET /api/v1/docs` 返回已发布文档的 `name`、首个一级标题 `title` 和读取 URL。
- `GET /api/v1/docs/{name}` 返回 UTF-8 Markdown 原文，媒体类型为 `text/markdown`。

发布列表只包含六份甲方文档：使用文档、模型算法、训练与调优、接口文档、部署文档、测试指南。名称通过固定映射解析，不接受任意文件路径；未知名称返回 404。每次请求直接读取 Markdown，使文件修改立即成为页面内容。

## 前端设计

保留现有业务 Tab。`api/static/index.html` 顶栏新增“帮助”菜单，其中“使用文档”进入 `/help`，“API 调试文档”进入现有 Swagger `/docs`。

新增 `api/static/docs.html` 作为独立阅读页：顶部显示品牌、返回控制台与 API 参考入口；桌面端使用左侧文档导航和右侧正文，移动端将导航置于正文上方。页面首次加载调用文档列表接口，再加载首篇文档；切换文档时重新请求 Markdown 并用固定版本的轻量 Markdown 渲染器显示。HTML 仅包含布局、加载态和错误态，不含任何文档正文。

## 数据流与错误处理

`docs/*.md` → 文档读取 API → `/help` 页面 → Markdown 渲染。文档目录不可用、文档缺失或网络失败时，API 返回明确状态码，页面显示错误信息和重试入口；不会退回到内嵌的第二份正文。

## 测试与验收

新增轻量 pytest：验证文档列表顺序、已发布文档读取、Markdown 媒体类型、未知名称 404、内部文档不可访问，以及 `/help` 路由和顶栏入口。静态检查确认页面只从 API 加载正文。最终启动服务后验证：访问控制台顶栏“帮助”→“使用文档”→ `/help`，可切换并阅读刚更新的六份 Markdown。
