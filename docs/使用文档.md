# SleepFM-Clinical 使用文档

## 快速开始

### 打开控制台

服务部署后，浏览器访问 `http://<host>:6006/`。顶栏“帮助”可进入使用文档或 Swagger API 参考页。开始推理前，先在“系统状态”确认三个模型均已加载。

### 健康检查

```bash
curl http://<host>:6006/api/v1/health
```

返回 `status: healthy`，且 `models_loaded` 中三项均为 `true`，表示服务已就绪。

### 使用 Demo EDF 完成一次推理

网页操作：进入“完整推理”，上传 `notebooks/demo_data/demo_psg.edf`，填写真实年龄 `3`、性别“女性 (0)”，勾选睡眠分期与疾病预测后提交。Demo 通常约 30–60 秒完成；实际耗时取决于 EDF 时长、磁盘、CPU、GPU 和当前任务队列。

命令行调用：

```bash
curl -X POST http://<host>:6006/api/v1/predict \
  -F "file=@notebooks/demo_data/demo_psg.edf" \
  -F "age=3" \
  -F "gender=0" \
  -F "tasks=sleep_staging,disease_prediction"

curl http://<host>:6006/api/v1/task_status
curl http://<host>:6006/api/v1/task_result
```

当 `task_status` 的 `stage` 为 `done` 后读取 `task_result`。结果读取后会从内存结果区取走，请及时保存。

## 控制台功能

### 完整推理

一次完成 EDF 预处理、嵌入生成及选定下游任务。疾病预测必须填写年龄和性别；可用 `min_hazard_score` 过滤展示结果。

### 数据预处理

将 EDF 重采样并转换为 HDF5，展示通道匹配、采样率和时长。结果返回 `preprocessed_file_id`，可直接供“生成嵌入”复用。

### 生成嵌入

接受 EDF、HDF5、文件 URL 或 `preprocessed_file_id`，输出四类模态的 128 维时序嵌入，并返回 `embedding_file_id`。

### 睡眠分期

接受 EDF、嵌入 HDF5、文件 URL 或 `embedding_file_id`，输出每个 5 秒时段的 Wake、N1、N2、N3、REM 概率及汇总。

### 疾病预测

接受与睡眠分期相同的输入，并结合年龄、性别输出疾病风险排序。`hazard_score` 是相对风险模型分数，不是临床诊断或校准后的绝对发病概率。

### 系统状态与疾病标签

“系统状态”展示模型、GPU、内存和任务状态；“疾病标签”展示 `label_idx`、PheCode 与疾病名称映射。

## API 调用流程

### 异步子任务接口

`/api/v1/preprocess`、`/api/v1/embed`、`/api/v1/sleep_staging`、`/api/v1/disease_prediction` 提交后立即返回：

```json
{"status":"accepted","task_id":"sub_xxxxxxxxxxxx"}
```

使用返回的任务 ID 轮询；`status` 可能为 `running`、`success` 或 `error`：

```bash
curl http://<host>:6006/api/v1/subtask_result/{task_id}
```

常用调用示例：

```bash
# 1. EDF 预处理
curl -X POST http://<host>:6006/api/v1/preprocess \
  -F "file=@notebooks/demo_data/demo_psg.edf"

# 2. 复用预处理文件生成嵌入
curl -X POST http://<host>:6006/api/v1/embed \
  -F "preprocessed_file_id=preproc_xxxxxxxxxxxx"

# 3. 复用嵌入进行睡眠分期
curl -X POST http://<host>:6006/api/v1/sleep_staging \
  -F "embedding_file_id=embed_xxxxxxxxxxxx"

# 4. 复用嵌入进行疾病预测
curl -X POST http://<host>:6006/api/v1/disease_prediction \
  -F "embedding_file_id=embed_xxxxxxxxxxxx" \
  -F "age=45" -F "gender=1"
```

每个子任务的成功结果只返回一次；客户端取得 `success` 后应保存结果和文件 ID。

### 完整推理接口

`POST /api/v1/predict` 只接受 EDF 上传或 `file_url`。它使用全局任务状态：提交后轮询 `GET /api/v1/task_status`，完成后调用一次 `GET /api/v1/task_result`。同一时间已有完整推理时返回 `status: busy`。

### 下载导出文件

子任务结果或完整推理结果会给出文件 ID 和 `download_url`。也可直接调用：

```bash
curl -OJ http://<host>:6006/api/v1/download/{file_id}
```

HDF5 用于复用预处理/嵌入，JSON 用于保存睡眠分期或疾病预测结果。

## 参数说明

| 参数 | 说明 |
| --- | --- |
| `file` | 表单上传；完整推理仅接受 EDF，子任务按接口接受 EDF/HDF5 |
| `file_url` | 服务端可访问的文件 URL；与 `file` 二选一 |
| `age` | 填真实年龄，范围 0–150；后台计算 `age / 100` 后送入模型 |
| `gender` | `0 = 女性`，`1 = 男性` |
| `tasks` | 完整推理任务，逗号分隔：`sleep_staging,disease_prediction` |
| `min_hazard_score` | 可选，只过滤返回列表，不改变模型推理 |
| `preprocessed_file_id` | 复用本服务导出的预处理 HDF5 |
| `embedding_file_id` | 复用本服务导出的嵌入 HDF5 |

## 结果与文件复用

导出文件保存在服务端 `exports/`。预处理、嵌入和结果文件设计为临时交换文件，保留窗口为 24 小时；下载接口会清理超过该期限的文件，过期后返回 404。生产调用方应在任务成功后立即下载，不要把文件 ID 当作永久存储地址。

推荐复用链路：一次 `/preprocess` → 一次 `/embed` → 使用同一个 `embedding_file_id` 分别调用睡眠分期和疾病预测，可避免重复预处理和基座模型计算。

## 常见问题

### 提示缺失通道或没有匹配模态

当前部署链路要求 EDF 至少匹配 BAS（脑电/眼电）、RESP（呼吸）、EKG（心电）、EMG（肌电）四组中的各一个通道。先在预处理结果检查通道名；若未匹配，应修正 EDF 标签或 `sleepfm/configs/channel_groups.json` 后重新处理。

### 返回 `busy`

完整推理采用单任务状态管理。等待当前任务完成，再重新提交；期间可查看 `/api/v1/task_status`。不要并发重复上传同一文件。

### GPU 占用高或任务排队

嵌入、睡眠分期和疾病预测通过进程内 GPU 锁串行使用 GPU，以避免显存争用。并发子任务会等待锁释放，等待时间不代表任务失败。

### 结果下载返回 404

文件 ID 可能填写错误或已超过 24 小时。重新运行对应步骤并在成功后及时下载。

### 耗时超过 Demo 参考

30–60 秒仅是仓库 Demo 的经验范围，不是服务等级承诺。长时 EDF、网络 URL、CPU 预处理、GPU 型号、磁盘性能及并发等待都会增加耗时。
