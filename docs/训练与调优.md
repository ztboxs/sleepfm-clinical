# SleepFM-Clinical 训练与调优方案

## 适用范围

本方案用于基座模型继续预训练、睡眠分期微调和疾病风险模型微调。当前 API 只加载既有检查点；训练产物必须先离线验收，再按部署文档替换对应模型目录。训练过程不应直接修改在线推理逻辑。

## 数据准备

1. 汇总 EDF、数据集名称、受试者 ID、设备/导联信息与采样率。
2. 统一通道名称到 `sleepfm/configs/channel_groups.json` 的 BAS、RESP、EKG、EMG 分组。
3. 按受试者划分 train/validation/test，禁止同一受试者跨集合，避免数据泄漏。
4. 睡眠分期准备与记录时间对齐的标签；疾病任务准备 `is_event.csv`、事件/随访时间文件及人口学特征。
5. 训练前完成去标识化、用途授权、保存期限和访问权限确认。真实患者数据、密钥和内部存储地址不得提交到 Git。

## 训练流程

以下命令从仓库根目录开始；运行训练前先复制 YAML 为项目专用配置并填写本地路径。

### EDF 预处理

```bash
python sleepfm/preprocessing/preprocessing.py \
  --root_dir /data/edf \
  --target_dir /data/hdf5_128 \
  --resample_rate 128 \
  --num_threads 4
```

抽样检查 HDF5 通道、时长、数值范围和缺失率，再生成受试者级 `dataset_split.json`。

### 自监督预训练

```bash
cd sleepfm/pipeline
python pretrain.py \
  --config_path ../configs/config_set_transformer_contrastive.yaml \
  --channel_groups_path ../configs/channel_groups.json
```

使用 `mode: leave_one_out` 训练 LOO-CL；恢复训练时传 `--checkpoint_path <run_dir>`。保存配置、权重、代码版本、数据版本和训练日志。

### 嵌入生成

```bash
cd sleepfm/pipeline
python generate_embeddings.py \
  --model_path ../checkpoints/model_base \
  --dataset_name project_dataset \
  --channel_groups_path ../configs/channel_groups.json \
  --split_path ../configs/dataset_split.json \
  --splits train,validation,test
```

嵌入应由同一基座检查点统一生成；更换基座权重后，下游训练集与验证集嵌入必须全部重建。

### 睡眠分期微调

```bash
cd sleepfm/pipeline
python finetune_sleep_staging.py \
  --config_path ../configs/config_finetune_sleep_events.yaml \
  --channel_groups_path ../configs/channel_groups.json \
  --split_path ../configs/dataset_split.json
```

按类别报告 precision、recall、F1 和混淆矩阵，同时报告 macro-F1 与总体准确率。类别不均衡时优先以 macro-F1 和少数类召回率作为选择标准。

### 疾病预测微调

1065 标签任务使用：

```bash
cd sleepfm/pipeline
python finetune_disease_prediction.py \
  --config_path ../configs/config_finetune_disease_prediction.yaml \
  --channel_groups_path ../configs/channel_groups.json \
  --split_path ../configs/dataset_split.json
```

较小 CoxPH 标签集可使用 `finetune_diagnosis_coxph.py`。标签事件数过少时不得只报告训练损失，应预先设定最小事件数、置信区间和不予发布规则。

## 配置与起始参数

| 来源 | batch size | 学习率 | epoch | 说明 |
| --- | ---: | ---: | ---: | --- |
| 论文参考：基座预训练 | 32 | 0.001 | 1 | 用于复现实验的参考起点 |
| 论文参考：下游微调 | 32 | 0.001 | 10 | 文中下游训练参考，LSTM 为 2 层 |
| 仓库预训练示例 YAML | 128 | 0.001 | 2 | 6 层 Transformer；示例值不等于论文设置 |
| 仓库睡眠分期示例 YAML | 16 | 0.001 | 2 | 示例限制 `max_files: 100`，正式训练须调整 |
| 仓库疾病示例 YAML | 32 | 0.001 | 21/10 | 分别对应不同标签集配置 |

当前随服务交付的检查点配置还可能不同，例如睡眠分期 20 epochs、1065 类疾病模型 40 epochs；部署和复现实验均以各模型目录内的 `config.json` 为准。

仓库 YAML 含原作者环境的原型绝对路径。使用前必须替换 `data_path`、`model_path`、`split_path`、`labels_path`、`demo_labels_path` 和保存目录，不要在代码中增加路径兼容分支。显存不足时先减小 batch size，再评估梯度累积；每次只改变少量超参数并固定随机种子。

## 评估与验收

验收指标必须在调优前书面确定，并在未参与调参的固定测试集上计算：

- 睡眠分期：macro-F1、各阶段 F1/召回率、准确率、混淆矩阵；按数据集、设备和人群分层。
- 疾病预测：每个目标的 C-index、事件数、置信区间及必要的多重检验；如输出概率，另做时间窗校准。
- 工程指标：模型加载成功率、单记录耗时、峰值显存/内存、失败率和通道覆盖率。
- 回归要求：使用固定 Demo 和代表性样本比较新旧版本，保存配置、权重哈希、代码提交号和结果文件。

只有达到预设验收指标且无关键分层明显退化，才可进入部署评审。测试集结果不得反向用于继续选参。

## 向项目方提交调优请求

每个调优请求至少填写以下内容；缺项会影响工作量评估与验收：

| 项目 | 必填内容 |
| --- | --- |
| 任务定义 | 预训练、睡眠分期或疾病预测；业务用途与不在范围内的事项 |
| 目标人群 | 年龄、地区、机构、设备、纳入/排除条件 |
| 通道清单 | EDF 实际标签、单位、采样率及 BAS/RESP/EKG/EMG 映射 |
| 数据规模 | 受试者数、记录数、总小时数、阳性/事件数、缺失率 |
| 标签定义 | 标注规范、时间窗口、PheCode/终点、冲突处理规则 |
| 划分策略 | 受试者级 train/validation/test 与外部验证集来源 |
| 验收指标 | 主指标、最低门槛、置信区间、重点分层和最大允许退化 |
| 算力限制 | GPU 型号/数量、显存、最大训练时长和存储预算 |
| 合规授权 | 去标识化状态、数据用途授权、访问人和保存/销毁要求 |
| 期望交付物 | 权重、配置、报告、日志、复现命令、接口回归结果及截止日期 |

建议标题采用“`[数据集]-[任务]-[目标指标]-[截止日期]`”，附件只提供去标识化的数据字典和样例结构；实际数据通过获批的受控存储交付。

## 交付物

- 最终检查点及配套 `config.json`、通道映射、标签映射；
- 数据版本、划分文件哈希、代码提交号和完整复现命令；
- 训练曲线、验证/测试指标、分层结果、失败案例和已知限制；
- 与现网模型的回归对比及部署建议；
- 模型卡或版本说明，包含适用人群、禁用场景和回滚版本。

## 注意事项

- 不在真实数据路径上直接修改仓库示例配置，使用独立项目配置并纳入受控版本管理。
- 不把患者 EDF、派生 HDF5、人口学明细、访问令牌或内部绝对路径提交到仓库。
- 调优阈值必须来自验证集，测试集只用于最终一次验收。
- 更换通道映射、预处理规则、基座检查点或标签定义都视为模型版本变更，需要重新评估。
- 疾病 `hazard_score` 不应在未经目标人群校准时解释为绝对风险概率。
