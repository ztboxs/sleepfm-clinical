## 1. 项目概述

基于 [SleepFM](https://github.com/zou-group/sleepfm-clinical)（Nature Medicine 发表）多模态睡眠基础模型，将其封装为标准 HTTP API 服务。支持上传 EDF 格式多导睡眠图（PSG）文件，自动完成睡眠分期（5 类）和 1065 种疾病的 Cox 风险预测。

### 核心能力

| 能力 | 说明 |
|------|------|
| **睡眠分期** | 逐 5 秒时段分类为 Wake / N1 / N2 / N3 / REM |
| **疾病风险预测** | 基于 PSG 嵌入 + 人口学特征，预测 1065 种疾病的 Cox 比例风险 |
| **Web 界面** | 内置中文 Meta 风格测试控制台，浏览器即可使用 |

## 3. 模型说明

系统使用三个级联模型，均在启动时一次性加载到 GPU：

| 模型 | 类名 | 检查点路径 | 参数量 | 功能 |
|------|------|-----------|--------|------|
| 基座模型 | `SetTransformer` | `sleepfm/checkpoints/model_base/best.pt` | 4.44M | PSG 信号 → 128 维嵌入向量 |
| 睡眠分期 | `SleepEventLSTMClassifier` | `sleepfm/checkpoints/model_sleep_staging/best.pth` | 1.19M | 嵌入向量 → 5 类睡眠阶段 |
| 疾病预测 | `DiagnosisFinetuneFullLSTMCOXPHWithDemo` | `sleepfm/checkpoints/model_diagnosis/best.pth` | 0.91M | 嵌入 + 人口学特征 → 1065 种疾病 Cox 风险 |

## 4. 推理流程

### 端到端推理管线

```
EDF 文件上传
    │
    ▼
[Step 0] 预处理 (EDF → HDF5)
    │  - 通道匹配 (BAS/RESP/EKG/EMG 四模态)
    │  - 128Hz 重采样
    │  - 低通滤波 (Butterworth, order 4)
    │  - Z-score 归一化 (per-channel)
    ▼
[Step 1] 嵌入生成 (SetTransformer)
    │  - 按 5 分钟分块 (38400 samples)
    │  - 每个模态独立前向传播
    │  - 输出: 5 秒级嵌入 (128 维) + 5 分钟聚合嵌入
    ▼
┌───────────────────┬─────────────────────────┐
│ [Step 2a] 睡眠分期 │ [Step 2b] 疾病预测       │
│                   │                         │
│ 输入: 5秒级嵌入    │ 输入: 5秒级嵌入 + age/gender │
│ 模型: SleepEventLSTM│ 模型: DiagnosisCOXPH    │
│ 输出: 5类概率/epoch │ 输出: 1065种疾病风险值    │
└───────────────────┴─────────────────────────┘
    │
    ▼
返回 JSON 结果
```

### 数据格式

**输入：**
- EDF 文件：多导睡眠图 (PSG) 标准格式，必须包含 BAS/RESP/EKG/EMG 四种模态通道
- 人口学信息（疾病预测必需）：年龄（归一化 0~1）、性别（0=女/1=男）

**输出 - 睡眠分期：**
- 每 5 秒一个 epoch 的 5 类概率分布 (Wake/N1/N2/N3/REM)
- 各阶段统计摘要（数量、占比）

**输出 - 疾病预测：**
- 1065 种疾病的 Cox 比例风险评分（Top 20 排序）
- 疾病 Phecode 编码和表现型名称映射

## 8. 关键实现细节

### 8.1 模型加载策略

- **启动时加载**：通过 FastAPI `lifespan` 事件，在服务启动时一次性加载三个模型到 GPU
- **单例模式**：`ModelsManager` 使用全局单例，避免重复加载
- **推理优化**：使用 `torch.no_grad()` 减少显存占用
- **设备适配**：自动检测 CUDA 可用性，无 GPU 时回退 CPU

### 8.2 DataParallel 权重处理

原项目使用 `nn.DataParallel` 训练，检查点中权重 key 带有 `module.` 前缀。
API 服务在单 GPU 上运行，加载时需要去除：

```python
state_dict = checkpoint.get("state_dict", checkpoint)
new_state_dict = {}
for k, v in state_dict.items():
    name = k.replace("module.", "") if k.startswith("module.") else k
    new_state_dict[name] = v
model.load_state_dict(new_state_dict)
```

### 8.3 GPU 并发控制

使用 `asyncio.Lock` 对 GPU 推理操作加锁，防止多个请求同时占用 GPU 导致 OOM：

```python
gpu_lock = asyncio.Lock()

async def predict(request):
    async with gpu_lock:
        result = await run_inference(request)
    return result
```

同一时刻仅允许一个推理请求使用 GPU，非 GPU 任务（健康检查、标签查询）不受影响。

### 8.4 临时文件管理

- 上传的 EDF 文件保存到系统临时目录
- 中间产物（HDF5、embedding HDF5）也存于临时目录
- 推理完成后自动清理所有临时文件
- 使用 Python `tempfile` 模块管理

### 8.5 CORS 配置

允许所有来源跨域访问（开发/测试环境）：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 11. 生产环境部署


创建服务文件 `/etc/systemd/system/sleepfm-api.service`：

```ini
[Unit]

After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/autodl-tmp/work/sleepfm-clinical
Environment="PATH=/root/miniconda3/envs/sleepfm_env/bin:/usr/bin"
ExecStart=/root/miniconda3/envs/sleepfm_env/bin/python -m api.main
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable sleepfm-api
systemctl start sleepfm-api
systemctl status sleepfm-api
```

## 13. 常见问题排查

### Q1: 启动时报 CUDA out of memory

三个模型总计约 6.5M 参数，显存占用较小（约 200MB）。如果 OOM，检查是否有其他进程占用 GPU：

```bash
nvidia-smi
# 终止占用进程
kill -9 <PID>
```

### Q2: 端口 6006 被占用

```bash
# 查看占用进程
fuser 6006/tcp

# 强制释放
fuser -k 6006/tcp
```

或修改 `api/config.py` 中的 `API_PORT`。

### Q3: EDF 文件通道不匹配

错误示例：

```
EDF 文件的通道无法匹配所有必需的模态。
缺失模态: ['BAS', 'EKG']
```

EDF 文件必须包含 BAS/RESP/EKG/EMG 四种模态的通道。通道名须与 `sleepfm/configs/channel_groups.json` 中定义的一致（区分大小写）。

推荐先用项目自带的 `notebooks/demo_data/demo_psg.edf` 验证服务正常。

### Q4: 推理耗时过长

以 `demo_psg.edf`（~2.4 小时 PSG 记录）为参考：

| 阶段 | 耗时 |
|------|------|
| 预处理 | ~10 秒 |
| 嵌入生成 | ~15 秒 |
| 睡眠分期 | <1 秒 |
| 疾病预测 | <1 秒 |
| **合计** | **~30 秒** |

实际耗时与 EDF 文件时长和 GPU 性能线性相关。8 小时完整 PSG 记录约需 60 秒。

### Q5: pip install 报错

确认在正确的 conda 环境下操作：

```bash
conda activate sleepfm_env
which python  # 应指向 sleepfm_env 环境
pip install fastapi "uvicorn[standard]" python-multipart
```

### Q6: 模型检查点文件缺失

确认以下三个文件存在且非空：

```bash
ls -lh sleepfm/checkpoints/model_base/best.pt
ls -lh sleepfm/checkpoints/model_sleep_staging/best.pth
ls -lh sleepfm/checkpoints/model_diagnosis/best.pth
```

### Q7: age 参数如何归一化？

项目使用线性缩放到 0~1 区间。Demo 数据中 `age=0.0306` 对应较年轻的受试者。具体归一化公式需参考原始训练数据的处理方式。

## 附录：EDF 文件兼容性

### 通道匹配要求

模型要求 EDF 文件包含**全部四种模态**，每种至少 1 个通道：

| 模态 | 说明 | 常见匹配通道名 |
|------|------|---------------|
| **BAS** | 脑电/眼电 | `C3-A2`, `C4-A1`, `F3-M2`, `O1-M2`, `EOG(L)`, `EOG(R)`, `EEG`, `E1`, `E2` |
| **RESP** | 呼吸 | `Airflow`, `SpO2`, `Chest`, `Abd`, `Nasal`, `Pulse`, `PPG`, `SaO2` |
| **EKG** | 心电 | `EKG`, `ECG`, `ECG II`, `ECG1`, `ECG2` |
| **EMG** | 肌电 | `EMG`, `Arm EMG`, `Chin`, `Chin EMG`, `LEG(L)`, `LEG(R)`, `Leg L`, `Leg R` |

完整支持列表见 `sleepfm/configs/channel_groups.json`。

### 已知不兼容数据集

| 数据集 | 原因 |
|--------|------|
| Sleep-EDF (Cassette/Telemetry) | 通道名格式不同（如 `EEG Fpz-Cz`）不在支持列表 |
