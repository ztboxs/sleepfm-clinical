## 1. 项目概述

基于 [SleepFM](https://github.com/zou-group/sleepfm-clinical)（Nature Medicine 发表）多模态睡眠基础模型，将其封装为标准 HTTP API 服务。支持上传 EDF 格式多导睡眠图（PSG）文件，自动完成睡眠分期（5 类）和 1065 种疾病的 Cox 风险预测。

### 核心能力

| 能力 | 说明 |
|------|------|
| **睡眠分期** | 逐 5 秒时段分类为 Wake / N1 / N2 / N3 / REM |
| **疾病风险预测** | 基于 PSG 嵌入 + 人口学特征，预测 1065 种疾病的 Cox 比例风险 |
| **Web 界面** | 内置中文 Meta 风格测试控制台，浏览器即可使用 |
| **任务拆解** | 每个子任务可独立执行，中间产物可导出复用 |
| **独立接口** | 睡眠分期和疾病预测可独立调用 |

## 3. 模型说明

系统使用三个级联模型，均在启动时一次性加载到 GPU：

| 模型 | 类名 | 检查点路径 | 参数量 | 功能 |
|------|------|-----------|--------|------|
| 基座模型 | `SetTransformer` | `sleepfm/checkpoints/model_base/best.pt` | 4.44M | PSG 信号 → 128 维嵌入向量 |
| 睡眠分期 | `SleepEventLSTMClassifier` | `sleepfm/checkpoints/model_sleep_staging/best.pth` | 1.19M | 嵌入向量 → 5 类睡眠阶段 |
| 疾病预测 | `DiagnosisFinetuneFullLSTMCOXPHWithDemo` | `sleepfm/checkpoints/model_diagnosis/best.pth` | 0.91M | 嵌入 + 人口学特征 → 1065 种疾病 Cox 风险 |

## 4. 推理流程

### 端到端推理管线

```
EDF 文件上传
    │
    ▼
[Step 0] 预处理 (EDF → HDF5)               → 可导出 HDF5 复用
    │  - 通道匹配 (BAS/RESP/EKG/EMG 四模态)
    │  - 128Hz 重采样
    │  - 低通滤波 (Butterworth, order 4)
    │  - Z-score 归一化 (per-channel)
    ▼
[Step 1] 嵌入生成 (SetTransformer)          → 可导出 HDF5 复用
    │  - 按 5 分钟分块 (38400 samples)
    │  - 每个模态独立前向传播
    │  - 输出: 5 秒级嵌入 (128 维) + 5 分钟聚合嵌入
    ▼
┌───────────────────┬─────────────────────────┐
│ [Step 2a] 睡眠分期 │ [Step 2b] 疾病预测       │   → 均可独立调用
│                   │                         │   → 结果可导出 JSON
│ 输入: 5秒级嵌入    │ 输入: 5秒级嵌入 + age/gender │
│ 模型: SleepEventLSTM│ 模型: DiagnosisCOXPH    │
│ 输出: 5类概率/epoch │ 输出: 1065种疾病风险值    │
└───────────────────┴─────────────────────────┘
    │
    ▼
返回 JSON 结果 + 导出文件 ID
```

### 数据格式

**输入：**
- EDF 文件：多导睡眠图 (PSG) 标准格式，必须包含 BAS/RESP/EKG/EMG 四种模态通道
- 人口学信息（疾病预测必需）：年龄（真实年龄 0~150，后台自动 `age/100` 归一化）、性别（0=女/1=男）

**输出 - 睡眠分期：**
- 每 5 秒一个 epoch 的 5 类概率分布 (Wake/N1/N2/N3/REM)
- 各阶段统计摘要（数量、占比）
- 支持按阶段筛选查看

**输出 - 疾病预测：**
- 1065 种疾病的 Cox 比例风险评分
- 疾病 Phecode 编码和表现型名称映射

## 8. 关键实现细节

### 8.1 年龄归一化

- 前端输入真实年龄（0~150 整数）
- 后端自动执行 `age_normalized = age / 100`
- 不采用 min-max 归一化，不采用 z-score 标准化
- 不使用数据集统计量（均值、标准差、最大最小值）

### 8.2 导出文件管理

- 预处理 HDF5、嵌入 HDF5、推理结果 JSON 自动保存到 `exports/` 目录
- 每个文件分配唯一 ID（如 `preproc_a1b2c3d4e5f6`）
- 文件保留 24 小时，过期自动清理
- 通过 `GET /api/v1/download/{file_id}` 下载

### 8.3 任务状态预检查

- 前端在提交推理任务前先调用 `GET /api/v1/task_status` 检查
- 如果有任务在运行，立即弹出提示（含当前进度、已运行时间、预估剩余时间），避免浪费上传时间
- 进度条实时显示预估剩余时间

### 8.4 GPU 并发控制

使用 `asyncio.Lock` 对 GPU 推理操作加锁，同一时刻仅允许一个推理请求使用 GPU。

### 8.5 临时文件管理

- 上传的 EDF 文件保存到系统临时目录
- 中间产物（HDF5、embedding HDF5）也存于临时目录
- 推理完成后自动清理临时文件
- 导出文件保存到 `exports/` 目录，独立于临时文件

```ini
[Unit]

After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/autodl-tmp/work/sleepfm-clinical
Environment="PATH=/root/miniconda3/envs/sleepfm_env/bin:/usr/bin"
ExecStart=/root/miniconda3/envs/sleepfm_env/bin/python -m api.main

RestartSec=10

[Install]
WantedBy=multi-user.target
```

## 13. 常见问题排查

### Q1: age 参数如何填写？

v2.0 起，`age` 参数输入**真实年龄**（如 45 岁填 `45`），后台自动执行 `age / 100` 归一化。

Demo 数据对应约 3 岁（`age=3`，归一化后 `0.03`）。

### Q2: 导出文件在哪里？多久过期？

导出文件保存在项目根目录的 `exports/` 文件夹中，保留窗口为 24 小时。调用 `GET /api/v1/download/{file_id}` 时会清理超过窗口的文件；生产调用方应在任务成功后及时下载。

### Q3: 如何复用预处理结果？

1. 调用 `POST /api/v1/preprocess` → 获得 `preprocessed_file_id`
2. 调用 `POST /api/v1/embed` 并传入 `preprocessed_file_id` → 跳过 EDF 读取

### Q4: 睡眠分期和疾病预测可以分开调用吗？

可以。分别使用 `POST /api/v1/sleep_staging` 和 `POST /api/v1/disease_prediction`，传入 `embedding_file_id` 即可。

### Q5: 推理耗时过长？

以 `demo_psg.edf`（~2.4 小时记录）为参考：

| 阶段 | 耗时 |
|------|------|
| 预处理 | ~10 秒 |
| 嵌入生成 | ~15 秒 |
| 睡眠分期 | <1 秒 |
| 疾病预测 | <1 秒 |
| **合计** | **~30 秒** |

复用预处理文件可节省约 10 秒。
